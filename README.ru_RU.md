# DoctorShop

Telegram-сервис платного общения клиентов с экспертами. Клиент выбирает эксперта и тариф,
оплачивает доступ через СБП и задает вопросы в боте. Эксперт отвечает, управляет собственными
ценами и создает заявки на вывод. Владелец управляет экспертами, тарифами, комиссиями,
платежами и пользователями.

Для каждой пары клиент–эксперт бот создаёт две нативные Telegram-темы: тему эксперта в
личном чате клиента с ботом и тему клиента в личном чате эксперта. PostgreSQL хранит связь
`chat_id + message_thread_id`, поэтому сообщения не могут попасть в чужую консультацию.

## Архитектура

- Python 3.12, aiogram 3, FastAPI;
- PostgreSQL, SQLAlchemy 2, Alembic;
- Redis для FSM;
- Taskiq для завершения подписок и напоминаний;
- Dishka-контейнер для дальнейшего расширения DI;
- транспортно-независимые сервисы в `src/application`;
- Telegram и HTTP являются адаптерами над общими бизнес-правилами.

Telegram-интерфейс разделён на небольшие feature-router-модули: клиент, консультации,
эксперт и административные разделы (`users`, `commerce`, `referrals`, `settings`,
`dashboard`). Общий `router.py` отвечает только за запуск, регистрацию, главное меню и
маршрутизацию сообщений из тем.

Основные таблицы: `users`, `expert_profiles`, `expert_applications`, `tariffs`,
`expert_tariffs`, `client_expert_subscriptions`, `payment_transactions`, `conversations`,
`conversation_messages`, `financial_ledger_entries`, `withdrawal_requests`,
`referral_rewards`, `broadcasts`, `settings` и `payment_gateways`.

## Запуск

1. Скопируйте `.env.example` в `.env` и заполните Telegram и PostgreSQL.
2. Для production укажите публичный `APP_DOMAIN`.
3. Запустите `docker compose -f docker-compose.local.yml up --build`.
4. Миграция выполняется entrypoint автоматически.
5. Пользователь с `BOT_OWNER_ID` сначала видит клиентское меню. Административная панель
   открывается отдельной кнопкой внизу и не меняет роль в базе.

Локальный Compose автоматически включает Telegram long polling, поэтому HTTPS-домен и
туннель для ручной проверки бота не нужны. Production-конфигурации используют webhook;
для них оставьте `BOT_USE_POLLING=false` и укажите публичный `APP_DOMAIN`.

## Темы консультаций в личных чатах

Перед проверкой переписки включите для бота режим тем:

1. Откройте `@BotFather` и выберите DoctorShop.
2. Откройте настройки бота и включите **Threaded Mode / Topics in private chats**.
3. Обязательно включите **Disallow users to create new threads**. Тогда клиенты, эксперты
   и владелец не смогут создавать, переименовывать и удалять темы: рабочие темы DoctorShop
   создаёт и обслуживает только бот.
4. Перезапустите приложение. При старте бот проверяет `getMe().has_topics_enabled` и отправляет
   владельцу предупреждение, если режим не включён или пользователям всё ещё разрешено
   создавать темы.

После подтверждённой оплаты Taskiq создаёт две темы. Одна пара клиент–эксперт всегда
использует один `Conversation` и две записи `ConversationTopic`; продление подписки повторно
использует эти же темы. При окончании подписки темы и история не удаляются, однако серверная
проверка останавливает передачу новых сообщений до продления.

Поддерживаются текст, фото, документы, голосовые сообщения, видео, аудио, анимации,
видеосообщения и стикеры. Медиа копируется средствами Telegram без загрузки на сервер.

В панели OWNER раздел **Темы консультаций** показывает состояния `PENDING`, `CREATING`,
`READY`, `FAILED` и `UNAVAILABLE`, позволяет повторить ошибки и создать темы для ранее
активированных подписок.

Локально без Docker:

```bash
uv sync
alembic -c src/infrastructure/database/alembic.ini upgrade head
uvicorn src.__main__:application --factory --reload
```

## СБП и webhook

Заполните `PLATEGA_MERCHANT_ID`, `PLATEGA_API_KEY` и `PLATEGA_SBP_PAYMENT_METHOD`.
Webhook провайдера:

```text
https://<APP_DOMAIN>/api/v1/payments/platega
```

Подпись проверяется заголовками `X-MerchantId` и `X-Secret`. Сумма webhook сверяется с
локальной транзакцией. Повторный webhook безопасен: подписка и проводки создаются один раз.
Без реквизитов приложение подключает `FakeGateway`; он предназначен только для разработки.

## Интерфейс и помощь

Главное меню, формы и подтверждения работают в одном редактируемом сообщении в общем чате.
В клиентском главном меню кнопка «Получить доступ к эксперту» выделена стилем `primary`
(синий цвет); остальные действия размещены в две колонки. Раздел «Мои консультации»
убран: консультации открываются через темы Telegram.
Текст, который пользователь вводит в формах, удаляется после обработки; сообщения внутри
тем консультаций сохраняются. У каждого нового системного уведомления есть кнопка
«✖️ Закрыть»: она удаляет само уведомление, включая фото или файл логов, сохраняя
меню, историю консультации и данные в базе. Telegram разрешает боту удалять такие
сообщения в течение 48 часов; более старые можно удалить вручную.
Бот принимает не более трёх нажатий
на inline-кнопки в секунду от одного пользователя.

Переписка передаётся только в тему собеседника, отдельная копия в общий чат не отправляется.
Лента Telegram «Все сообщения» может показывать сообщения всех тем: это отображение
одной истории, а не повторная отправка. Bot API не позволяет скрывать из неё сообщения
отдельных тем. Для просмотра конкретного диалога откройте его тему.

После каждого нового сообщения в рабочей теме бот переносит стартовое меню вниз в общий
чат отправителя, а после успешной доставки — также получателя. Новый экран отправляется
без звука (`disable_notification=True`), предыдущий удаляется. Если пользователь заполняет
форму, вниз переносится её текущий экран, состояние и введённые данные сохраняются.
Обновления одного меню выполняются последовательно через Redis-lock, чтобы одновременные
сообщения из разных тем не создавали несколько активных экранов. Повторная доставка одного
Telegram update не переносит меню заново.

В нижнем системном меню Telegram доступны команды `/start` и `/menu`. `/start` удаляет
предыдущий экран и создаёт чистое главное меню. Идентификатор активного экрана хранится в
PostgreSQL и Redis, поэтому очистка работает также после перезапуска приложения или Redis.

Ссылки на политику конфиденциальности и пользовательское соглашение задаются переменными
`PRIVACY_POLICY_URL` и `USER_AGREEMENT_URL`. Пока они пусты, кнопки показывают уведомление,
что ссылка ещё не настроена. `BOT_SUPPORT_USERNAME` открывает чат поддержки с подготовленным
текстом обращения.

Необязательные изображения экранов читаются из `BANNER_DIRECTORY` (по умолчанию
`assets/banners`) либо из JSON-словаря Telegram `file_id` в `BANNER_FILE_IDS`. Полный список
имён файлов находится в `assets/banners/README.md`; при отсутствии изображения используется
обычный текстовый экран.

Необработанные ошибки Telegram, HTTP и Taskiq записываются в `APP_LOG_PATH`; владельцу бот
отправляет `.log`-файл с контекстом, traceback и хвостом журнала без секретов.

## Комиссия и баланс

Формула чистого дохода эксперта:

```text
net = gross - gross × service_percent / 100
```

Сумма единой комиссии сервиса и процент фиксируются в транзакции. Изменение текущих
настроек не пересчитывает
историю. Баланс строится по неизменяемому ledger. Заявка на вывод атомарно резервирует весь
доступный баланс; отклонение создает обратную проводку.

## Фоновые задачи

- каждые 10 минут завершаются истекшие подписки;
- каждый час отправляется одно напоминание о подписке, которой осталось менее суток;
- модель рассылок поддерживает аудитории клиентов, экспертов и подписчиков.

Worker и scheduler запускаются отдельными сервисами Docker Compose.

## Роли

- `CLIENT`: регистрация, каталог экспертов, оплата, подписки и вопросы;
- `EXPERT`: сообщения, диалоги, цены, статистика, баланс и вывод;
- `OWNER`: клиентский интерфейс плюс защищённая административная панель. Эксперты,
  подписки, платежи, консультации и тарифы эксперта доступны из единой карточки пользователя.

Проверки доступа выполняются повторно в application services; скрытая кнопка не считается
защитой.

## Миграции и резервное копирование

```bash
alembic -c src/infrastructure/database/alembic.ini upgrade head
pg_dump -Fc -h "$DATABASE_HOST" -U "$DATABASE_USER" "$DATABASE_NAME" > doctorshop.dump
```

Перед production-обновлением всегда сохраняйте дамп. Исходная VPN-версия не является частью
DoctorShop; ее отдельный референс находится в соседнем проекте `NerfVPNShop2`.
