# Doctor Chatbot

Telegram-бот для платного общения клиентов с экспертами. Регистрация, выбор эксперта,
покупка подписки, переписка и управление тарифами выполняются через меню бота.

## Запуск через Docker

Нужны Docker Compose, токен Telegram-бота, Telegram ID владельца и настройки
платёжного провайдера. Создайте `.env` из `.env.example`, заполните
`BOT_TOKEN`, `OWNER_TELEGRAM_ID`, `POSTGRES_PASSWORD` и параметры Platega.

```bash
cp .env.example .env
# заполните .env
docker compose up --build -d
```

Эта команда поднимет PostgreSQL, применит миграции Alembic, запустит бота и
HTTP-сервис для уведомлений об оплате. Проверьте `docker compose ps` и
`docker compose logs -f bot web migrate`. Данные PostgreSQL сохраняются в
томе `postgres_data`; `docker compose down` том не удаляет.

Если том уже существовал, изменение `POSTGRES_PASSWORD` в `.env` само по себе
не меняет пароль пользователя внутри PostgreSQL. При ошибке
`password authentication failed` укажите первоначальный пароль или смените
пароль в существующей БД, сохранив её данные. Не используйте
`docker compose down -v` для «исправления» ошибки: эта команда удалит том БД.

В Platega включите способ оплаты через СБП, задайте его числовой ID в
`PLATEGA_SBP_PAYMENT_METHOD`, а также `PLATEGA_MERCHANT_ID` и `PLATEGA_API_KEY`.
В кабинете Platega укажите Callback URL
`https://ваш-домен/webhooks/platega` с методом POST. Домен должен иметь HTTPS
и проксировать запросы на порт `8080` сервиса `web`. По умолчанию Docker
публикует этот порт только на `127.0.0.1`; внешний доступ к webhook требует
обратного прокси. Без подтверждённого webhook подписка не активируется.
Настройки магазина, ключи и доступность СБП нужно проверить в личном кабинете
Platega перед боевым запуском. Новые платежи создаются через API Platega;
callback об успешной оплате, отмене или возврате обновляет локальную запись.

Для локальной демонстрации без реальных платежей можно задать
`PAYMENT_MODE=mock`, `ALLOW_MOCK_PAYMENTS=true`, случайный `MOCK_SECRET` и
`PUBLIC_BASE_URL` на доступный из Telegram браузера адрес сервиса `web`.
Ссылка тестовой оплаты активирует подписку без списания денег — этот режим
запрещено использовать для продаж.

## Что умеет бот

- Пользователь регистрируется с ФИО и телефоном; владелец получает уведомление.
- Клиент выбирает эксперта, видит его анкету и покупает тариф. По умолчанию
  миграция создаёт недельный тариф за 1000 ₽ с неограниченными сообщениями.
- Активная подписка открывает переписку. Сообщения подтверждаются перед
  отправкой, история сохраняется, ответы эксперта привязываются к вопросу.
- Пользователь подаёт анкету эксперта; владелец подтверждает, отклоняет или
  возвращает её на доработку. Эксперт устанавливает свои цены на тарифы.
- Владелец управляет тарифами, комиссиями, экспертами и заявками на вывод.
  Эксперт видит доход и создаёт заявку на вывод. Фактический перевод денег
  выполняется владельцем вне бота, затем отмечается как выплаченный.

Комиссии рассчитываются отдельно от полной суммы платежа:
`доход эксперта = сумма − комиссия платёжной системы − комиссия сервиса`.
Проценты и суммы фиксируются в записи успешного платежа, поэтому последующее
изменение настроек не переписывает историю. Повторный callback провайдера не
создаёт повторную подписку или доход.

## Локальный запуск без Docker

Установите зависимости (`uv sync`), задайте `DATABASE_URL`, примените миграции
`uv run alembic upgrade head`, затем отдельно запустите
`uv run python -m main` и `uv run uvicorn web.app:app --host 127.0.0.1 --port 8080`.
Если таблицы были когда-то созданы старым `create_tables()`, отметьте базовую
схему `uv run alembic stamp 20261005_01`, затем выполните `upgrade head`.

Для безопасности держите `.env` вне системы контроля версий, не публикуйте
токен бота и ключ Platega, используйте HTTPS для callback. Разработческий
mock-платёж отключён по умолчанию.
